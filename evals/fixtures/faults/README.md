# Synthetic form-fault fixtures — not validation footage

Regenerate with `npm run fixtures:faults`. Each JSON records its source demo, exact perturbation, labeled fault IDs, evaluated IDs, and raw landmark rep window. The generator crops each demo at the first count using the production pipeline. It preserves the source image dimensions, timestamps and unmodified joints, except where the documented operator changes them. Both sides are perturbed so near-side selection cannot hide the target.

There are 19 positive cases (one per catalog fault) and four unmodified first-demo-rep negatives, presumed clean. **All 23 are marked synthetic**: the demos are generated demonstration footage, not real human fault labels. Positive cases have only their intended fault annotated. Other faults may be side effects or pre-existing demo imperfections; their truth is unknown, so they are excluded with `evaluated: [target_id]`, rather than silently labeled absent. The four clean negatives evaluate every fault for that exercise. This masking is used identically by local metrics and LangSmith summary evaluators.

Operators include knee translations, wrist/shin separation, upper-body contraction or lean, partial elbow arcs, hip/ear translations, and timestamp compression. Positive joint displacements are deliberately large (sometimes anatomically implausible), to exercise predicate direction and coordinate conventions. These are regression/smoke tests, not representative biomechanics or independent accuracy evidence. The JSON `perturbation` field gives the exact magnitude and affected landmarks for each case.

The first experiment detected every target, but seven detectors also fired on a presumed-clean demo. We keep those false positives and the starting PLAN fault thresholds; we do not tune away ambiguous demo geometry to claim success. Every fault has only one labeled positive and one labeled negative. Confidence intervals and real-world accuracy cannot be inferred from these tiny, correlated examples.

Only synthetic precision >= 0.85 allows Tier A **provisional** status. No synthetic result unlocks Tier B. Real precision is N/A for every detector until Raz supplies labeled clips; Tier B additionally requires two consecutive observed reps and `view_ok`. Low tracking or off-profile view suppresses every form claim, including provisional A.

`analyzeRep` accepts an explicitly bounded rep/attempt window. It does not require the rep to have counted, so partial attempts can be evaluated. The caller must supply rep boundaries; live workout segmentation/integration remains M6. Provide `baselineTorsoLength` from standing setup when a window does not start standing. Otherwise the first valid torso length is used. Stationary windows are ignored by a small motion-excursion guard (10 degrees, or 0.15 torso lengths for push press); these are prototype segmentation assumptions, not new rep-count thresholds.

`RepReporter` emits schema-valid, compact reports with only speech-eligible faults. All observations, including locked B faults, are returned separately for logging. Callers must provide evaluation evidence explicitly; the default is fail-closed (no speech-eligible faults). `CuePolicy` selects one priority fault, at most two nudges per fault per set, with a different reminder and a fixed acknowledgment after clearing. The original long back-round first cue is retained in the shared bank; the policy selects a <=14-word alternative. Voice scheduling, the 25–55% talk-ratio target, actual TTS, and agent integration are later milestones.

## LangSmith

`npm run evals` uploads/builds `jax-rep-counting` and `jax-form-faults`, then runs both experiments locally against the exact production functions. Bind `LANGSMITH_API_KEY` only for this server-side command. No videos, camera images or keys are uploaded. Counting has 16 rows: four demo sequences and three negatives replayed with each of four exercises. Faults has the 23 cases described above.

Uploads use deterministic content-derived example IDs; repeated runs do not duplicate identical examples or delete existing datasets. An experiment uses only its current example IDs, not unrelated rows in an existing dataset. Changed fixtures produce new IDs. Results and API/SDK-generated URLs are saved in `evals/results/m3-perception.json`. Precision is TP/(TP+FP), recall TP/(TP+FN); undefined denominators are N/A, never zero or one by convention. Synthetic and real evidence are tallied separately.
